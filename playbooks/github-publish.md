# GitHub 发布

## 适用条件

准备把本地改动推送到 GitHub 或其他远端仓库，或要求创建仓库、tag、PR、Release、
Pages 部署与发布文案时使用。

## 发布前

1. 确认仓库、分支、远端和本次改动范围。
2. 检查 `git status` 与待提交 diff，不混入无关文件。
3. 核对本地 Git 身份，不执行 `git config user.*` 写入。
4. 检查提交信息，不添加 `Co-authored-by`、`Generated-by` 等 Agent 署名。
5. 检查 README、LICENSE、包元数据和版权信息是否被意外改写。
6. 新建、更名或公开项目时，检查个人站项目索引是否需要同步。

## 提交

使用 Conventional Commits 或维护者第一人称，只描述真实变更：

```text
feat: 新增工作流记录模板
fix: 修正演进时间线中的失效链接
docs: 补充发布前身份校验步骤
```

## 推送后

- 核对远端提交的作者与提交者。
- 核对 Pages 构建、目标页面和新增链接。
- 记录失败原因和修复方式，不只记录成功结果。

## 停止条件

身份不一致、待推送历史中存在 Agent 署名、版权归属被改写、即将混入无关改动或用户尚未
确认外部写操作时停止发布。
