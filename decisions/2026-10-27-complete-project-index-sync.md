# 新项目发布后的完整索引同步

日期：2026-10-27

状态：已采用

## 背景

`agent-craft` 首次公开发布时，个人站项目页和首页已经更新，但站点根 README 只有
分类概述，没有完整项目表。原发布规则写的是“项目表补一行”，没有处理“项目表原本
不存在”的情况，于是执行结果看起来更新过，实际上缺少一个稳定入口。

## 选项

1. 只维护项目总览页，首页和根 README 保持概述；
2. 保持三处人工同步，但继续依赖执行者自由判断；
3. 明确完整索引契约，所有相关入口在同一次发布中更新并相互校验。

## 决定

采用第三种。新公开项目发布完成必须同时满足：

- `docs/projects.md` 的速览表与分组正文都包含项目；
- `docs/README.md` 的公开仓库总数、导语、分类卡数量和编号一致；
- 站点根 README 的完整项目表包含每个公开项目，缺少表格时先创建；
- Pages 构建成功，公开页面和链接验证通过；
- 项目仓库与站点仓库分别提交。

侧边栏仅在页面增删时更新；其他外部入口仅在原本维护项目列表时同步，避免为了形式
统一制造无关修改。

## 结果与代价

每次发布需要检查更多文件，但“项目已经公开”与“所有公开入口都能找到它”成为同一个
完成条件。数量、分类和状态也能通过项目页速览表进行交叉核对。

## 复查条件

如果索引维护成本明显超过实际收益，再评估是否把三处展示改为从单一项目清单生成；
在此之前，不降低当前完整性要求。
